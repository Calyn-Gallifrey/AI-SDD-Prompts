# SDD2.0 简体中文主体规范

本文件是三项 SDD2.0 Skill、运行规则、资产模板和新生成 Feature 资产的唯一语言规则来源。其他文件只能引用，不得另行定义不同标准。

## 1. 适用范围

以下内容必须以简体中文为主体：

- `uaw-sdd-ai-coding`、`uaw-code-review`、`uaw-unit-test` 中面向人阅读的 Skill 指令和运行规则；
- Markdown、HTML 等面向人的模板、报告和说明；
- 新建或修订的九项 Feature 公开资产；
- 标题、说明、事实、判断、风险、问题、建议、验收标准、评审发现、测试结论和归档总结。

该规则不改变开发者入口。开发者仍然只需提交简要提示词并调用 `uaw-sdd-ai-coding`。

## 2. 必须遵守的写作规则

1. 标题、段落、表头、字段说明和结论先使用简体中文。
2. 能准确使用中文表达的内容不得整段改用英文，也不得生成中英文各一套的重复正文。
3. 用户输入为英文时，资产中的分析和结论仍使用简体中文；需要追溯的原文可按原样引用，并明确标注为“原始输入”或“外部契约原文”。
4. 不确定专业词如何翻译时，保留原英文术语并补充中文解释；不得为了追求全中文而改写代码或外部契约含义。
5. 人类可读正文不得使用繁体中文。外部专有名称或原始数据确需保留繁体时，必须标明其为原始值，不得扩散到说明文字。

## 3. 允许保留英文的内容

以下英文属于必要例外，可直接保留：

- Skill 名称、文件名、路径、Git 引用、命令、参数和环境变量；
- 代码标识符、类名、方法名、包名、注解、SQL、HTTP 方法与接口路径；
- JSON/YAML 键、Schema 字段、哈希、版本号、状态枚举和模式枚举；
- API、BO、DTO、VO、Entity、DDL、ORM、SDD、CI 等通用技术缩写；
- 已确认的外部系统、协议、错误码、字段名和数据字典原始值；
- 为精确检索或兼容机器处理而必须保持不变的固定字符串。

除固定字符串外，首次出现的专业英文应尽量采用“中文说明（English Term）”形式。英文例外不能成为整段英文正文的理由。

## 4. 生成资产要求

`brief-design.md`、`proposal-input.md`、`spec.md`、`design.md`、`tasks.md`、`code-review-findings.md`、`auto-fix-summary.md`、`unit-test-summary.md` 和 `archive.md` 必须满足：

- 人类可读内容以简体中文为主体；
- 代码、路径、命令、状态枚举和外部契约原文保持精确；
- 英文原文较长时，在相邻位置给出中文解释或结论；
- 不得只翻译标题而保留大段英文正文；
- 每次记录资产前通过控制器的语言校验。

## 5. 历史资产与来源档案边界

`execution_mode=historical-example` 且状态为 `superseded` 的既有 Feature 资产是不可变审计样例。为保持其哈希、修订和迁移证据，不回写翻译；它们不代表当前语言标准，也不得复制为新资产。

`original/` 保存导入时的原始工程规范和数据字典，是来源档案而不是当前运行规则。为保持来源原文、哈希映射和差异审计，不回写翻译；当前 Skill 不得直接加载该目录，面向运行的派生规则必须在 `references/` 中以简体中文表达，并由 `source-provenance.json` 记录来源关系。

## 6. 校验与阻塞

- 静态校验器检查三项 Skill 的当前人类可读运行文件是否具备简体中文主体。
- 控制器在 `init` 和 `record-artifact` 时检查公开资产；不符合要求时返回非零并阻塞流程。
- 语言校验只判断人类可读正文，不要求翻译机器键值、代码或外部原始值。
- 校验失败时先修订当前文件，再重试同一动作；不得绕过校验或手工修改控制状态。
