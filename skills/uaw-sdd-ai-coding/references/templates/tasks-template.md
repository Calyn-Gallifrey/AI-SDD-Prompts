## 7. Implementation Completion Review

This is a deterministic readiness check, not an additional inferred human gate. It passes only when:

- every declared Phase has a current human Phase Review approval;
- Git branch and worktree lock still match the feature;
- all changed production/test/config files are inside the approved scope;
- no unrelated pre-existing change was absorbed;
- the implementation snapshot is frozen with base commit, head/tree IDs, file hashes, and snapshot SHA-256;
- no Tasks/Design/Spec revision changed after its approval.

On pass, invoke `uaw-code-review` in `SDD_TASK_CODE_REVIEW` mode. On failure, remain `blocked` and follow `.sdd2/feature-state.json.next_required_action`.

## 8. Code Review Handoff

- Entry Mode: `SDD_TASK_CODE_REVIEW`
- Scope Authority: `./.sdd2/implementation-scope.json.frozen_snapshot`
- Required SDD Inputs: current approved Spec, Design, Tasks
- Output: `./code-review-findings.md`
- Findings are immutable first-pass evidence; fixes go in `auto-fix-summary.md`.
- Any implementation/test/config change after review invalidates review and requires a new freeze plus full re-review.

## 9. Auto-fix And Unit Test Handoff

- Auto-fix Output: `./auto-fix-summary.md`
- Unit Test Entry: `uaw-unit-test`, SDD mode
- Unit Test Output: generated/updated test source plus `./unit-test-summary.md`
- Unit Test Gate binds to the same scope hash as passed Code Review and closed Auto-fix.
- Manual/CI/IDE validation may supplement but cannot replace changed test source for production changes.
