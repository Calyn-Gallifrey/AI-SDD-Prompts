# SDD2.0 冻结版

冻结标签：`sdd2.0-frozen-2026-10-23`
控制器维护构建：`2.0-java8.3`
冻结范围：三项 Skill 的 63 个文件；逐文件模式、大小及 SHA-256 见 `manifest.json`。

## 使用

1. 解压本目录 `sdd2.0-skills.zip`，将其中完整的 `skills/` 复制到使用环境，保留原目录结构和文件字节。
2. 让 AI 工具加载 `uaw-sdd-ai-coding`、`uaw-code-review`、`uaw-unit-test`。
3. 命令行可执行 Java 8 及以上版本和 Git；控制器直接运行随包 JAR，不需要开发机重新编译。
4. 使用“简要提示词 + 调用 uaw-sdd-ai-coding Skill”入口。启动预检、流程控制和完整性校验由 Skill 内部执行。

业务项目的编译、单元测试仍需项目自身的构建工具、依赖和环境。Python 仅用于维护审计，Maven 在本轮用于业务 Demo 测试，都不属于控制器启动依赖。

`sdd2-control.jar` 与同目录 `sdd2-control.sha256` 必须配套。版本冻结后不再重建或覆盖这一对文件。

## 固定内容

- `sdd2.0-skills.zip`：可直接复制的完整技能包。
- `manifest.json`：63 个文件的模式、大小、哈希，包哈希以及审计证据哈希。
- `SHA256SUMS`：清单和 ZIP 的校验值。
- Git 标签固定最终提交，后续不移动或强推该标签。

维护环境可从仓库根目录运行 `python3 tools/freeze_sdd20.py`，验证源文件、包内文件、执行模式和审计证据。该命令不属于普通开发者入口；使用 ZIP 不要求安装 Python。

## 既有活动流程接续

从 `2.0-java8.2` 升级的活动冻结范围缺少新执行模式证据时，会报告范围漂移。由 Skill 按合同重新冻结，重做受影响代码评审、测试及归档步骤；不手工重写原批准链。该迁移路径已验证。

已归档历史记录保持只读；需要复核时使用其对应历史运行包。损坏的批准/事件链仍需保留现场并停止，不能把升级作为跳过证据检查的理由。

## 验证边界

- 反例和 Demo 使用脚本模拟批准，不证明真实模型在所有回合都会正确执行，也不认证聊天平台发件人。
- 工作流仍要求真实用户逐阶段审核；代码与测试的业务正确性、断言质量、真实内网项目集成需要对应现场证据。
- PATH 与已有版本化 Wrapper 属于可信工具链前提。其他操作系统、其他测试工具、真实数据库及外部接口未在本轮现场验收；无法识别的测试结果保持 blocked。
- 哈希与 Git 标签用于内容固定和漂移检测，不提供对具有仓库写权限者的防篡改认证。

后续仅在独立的 SDD2.1 开发分支处理用户明确的小升级；需求到 AI 简要设计的大升级按用户决定在阿里云桌面 AWS Kiro 中实施。完整安排见 `../../docs/SDD_VERSION_POLICY.md`。
