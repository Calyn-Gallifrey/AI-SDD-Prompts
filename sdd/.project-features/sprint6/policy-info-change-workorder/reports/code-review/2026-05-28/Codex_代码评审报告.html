CR-DEMO-001. 重复提交校验不是原子操作 P1

文件：uaw-sdd-demo/src/main/java/com/example/uawsdddemo/service/PolicyInfoChangeWorkOrderService.java；uaw-sdd-demo/src/main/java/com/example/uawsdddemo/repository/InMemoryPolicyInfoChangeWorkOrderRepository.java

位置：Service 34-38；Repository 16-28

问题描述：Service 先调用 existsSubmittedDuplicate，再调用 save。两个并发相同请求可能同时完成重复检查，然后都保存成功。

风险影响：违反重复提交控制目标；真实生产中可能产生重复待处理工单。

修复建议：将重复判断与保存合并为仓储层原子操作；真实 DB 实现应使用唯一索引、事务或业务幂等键。

优化前

if (repository.existsSubmittedDuplicate(workOrder)) {
    throw new BadRequestException("submitted duplicate policy info change work order exists");
}
return toResponse(repository.save(workOrder));

优化后

PolicyInfoChangeWorkOrder saved = repository.saveSubmittedIfAbsent(workOrder)
        .orElseThrow(() -> new BadRequestException("submitted duplicate policy info change work order exists"));
return toResponse(saved);

CR-DEMO-002. 接口缺少认证授权且返回敏感变更值 P1

文件：uaw-sdd-demo/src/main/java/com/example/uawsdddemo/controller/PolicyInfoChangeWorkOrderController.java；uaw-sdd-demo/src/main/java/com/example/uawsdddemo/model/dto/PolicyInfoChangeWorkOrderResponse.java

位置：Controller 26-34；Response 10-17

问题描述：创建和查询接口没有 CurrentUser / 权限校验；响应对象返回 oldValue、newValue、requester。

风险影响：一旦接入真实保单数据，可能越权查询并泄露手机号、邮箱、地址等敏感信息。

修复建议：接入认证和数据权限；按角色控制字段返回，对敏感字段脱敏。

优化前

public PolicyInfoChangeWorkOrderResponse get(@PathVariable String workOrderId) {
    return service.get(workOrderId);
}

优化后

public PolicyInfoChangeWorkOrderResponse get(@PathVariable String workOrderId) {
    CurrentUser user = currentUserProvider.get();
    return service.get(workOrderId, user);
}

CR-DEMO-004. 构建配置依赖实验参数 P2

文件：uaw-sdd-demo/pom.xml

位置：56-61

问题描述：Surefire 通过 -Dnet.bytebuddy.experimental=true 适配当前 Java 26 测试环境。

风险影响：当前测试能通过，但长期稳定性依赖 JDK / Mockito / Byte Buddy 组合。

修复建议：用 Maven Toolchains 或 CI 固定 Java 17；或升级到明确支持目标 JDK 的测试依赖。

优化前

<argLine>-Dnet.bytebuddy.experimental=true</argLine>

优化后

<plugin>
  <artifactId>maven-toolchains-plugin</artifactId>
  <!-- enforce Java 17 in build and test -->
</plugin>
