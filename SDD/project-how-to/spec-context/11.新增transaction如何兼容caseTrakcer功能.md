## 背景2：case tracker功能兼容新增transaction类型
* 
当需要新增transaction类型时，需要在 `TransactionTypeConfigEnum.java` 中新增对应的枚举项，并在字典表中插入对应的配置，才能实现case tracker功能兼容新增transaction类型。

### 枚举配置步骤
1. 在 `TransactionTypeConfigEnum.java` 中新增枚举项，例如：
```java
NEW_TRANSACTION_TYPE("trx_new_transaction_type"),
```

2. 在字典表中插入对应的配置，SQL示例如下：
```sql
-- 新增transaction类型初始化
DELETE FROM iic_crm_base_data WHERE type_name = 'trx_new_transaction_type';
INSERT INTO iic_crm_base_data (type_name, dict_code, `language`, `describe`, sort, status, created_by, updated_by, dae_country_code)
VALUES ('trx_new_transaction_type', 'transactionType1', 'en-US', 'transactionType1 name', 1, 0, 'SYSTEM', 'SYSTEM', 'ZA');
```

### SQL脚本生成规则
- `type_name`是新增transaction的类型，已知类型有`general information`,`my document`,`agreement information`,`change my personal detail`, transaction类型下可能有多种transaction type
- `dict_code`的值对应新transaction存入 `iic_crm_transaction.transaction_type`字段的值
- `describe`的值是新transaction的名称，用于页面展示

## 背景3：包结构规范
根据 `2.如何新增一个transaction业务功能包结构.md` 规范，Transaction业务功能包采用分层架构设计，主要包含以下四个核心子包：

```
transaction/
├── base/              # 基础层：定义基础常量、接口和抽象类
├── common/            # 公共层：提供跨业务模块的通用功能
├── core/              # 核心层：实现具体的业务功能模块
└── support/           # 支撑层：提供工具类、缓存、校验等支撑能力
```

### 包结构说明
- **base/**: 基础层，定义Transaction模块的基础常量、基础模型和基础服务接口
- **common/**: 公共层，提供跨业务模块共享的通用功能
- **core/**: 核心层，实现具体的业务功能模块，每个子模块代表一个独立的业务领域
- **support/**: 支撑层，提供工具类、缓存、校验等支撑能力

### 包创建规范
1. 每个包目录下**不需要**创建 `package-info.java` 文件
2. 使用标准包前缀：`com.ocft.iic.uaw.server.modules.transaction`
3. 包名全部小写，使用点号分隔，体现包的职责和层次
